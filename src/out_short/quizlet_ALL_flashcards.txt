A3 | Bind vs reverse payload - which beats a firewall?	Reverse: the target calls out to you (LHOST/LPORT). Bind: the target listens and you call in. Reverse wins, since outbound is usually allowed.  [Not all payloads call back - some just run commands, like creating a user.]

A3 | 3 ways Metasploit is customized?	It logs your commands, saves results in its database, and can be scripted.  [spool, msfdb, resource scripts.]

A4 | Where do wordlists come from?	Kali's built-in lists (rockyou.txt) or ones you generate yourself (crunch, cewl).
A4 | What stops a brute force attack?	Lockout, rate limiting, strong passwords, MFA, SSH keys only, alerts on failed logins.  [These are the 'defenses' feature.]

A5 | What is web delivery?	A one-line command you host; when it runs on the target it pulls your payload into memory.
A5 | How does Microsoft fight phishing docs?	Protected View and blocking macros in files from the internet, so the user has to click Enable Content.

B1 | Which is FALSE?  (A) Bash can't use the network, so attackers ignore it  (B) You reach Linux through terminals and pseudoterminals running shells  (C) Bash keeps state in options, variables and environment variables  (D) A shell acts differently based on how it's configured and started	Bash can't use the network, so attackers ignore it  [Bash CAN talk over the network - reverse shells and exfil. B1 | Login vs non-login shell - why care?	They read different files, so the shell behaves differently. Login: /etc/profile + ~/.bash_profile. Non-login: ~/.bashrc.
B1 | Two Bash conveniences from 1.7?	Aliases (shortcuts for commands) and jobs (several tasks in one session).  [& , Ctrl+Z, jobs, fg, bg.]
B2 | Which tool pairing is right?  (A) adduser is low level, useradd is a Perl script  (B) usermod creates users  (C) useradd/userdel = low level; adduser/deluser = Perl scripts on Mint & Ubuntu; usermod = change a user  (D) They're all the same command	useradd/userdel = low level; adduser/deluser = Perl scripts on Mint & Ubuntu; usermod = change a user  [2.4 exactly.]
B2 | The 4 account files?	/etc/passwd, /etc/shadow, /etc/group, /etc/gshadow.  [Hook: passwd + shadow for users, group + gshadow for groups. Hashes live in shadow.]
B2 | 3 states an account can be in?	Locked, unlocked, expired.  [Lock = '!' in front of the hash (passwd -l).]
B2 | Expired password vs expired account?	Expired password = change it at login. Expired account = you can't log in at all.
B2 | What is /etc/nologin?	If that file exists, nobody but root can log in - and they see its message.  [Used during maintenance.]
B2 | What does chfn change?	The user's name/office/phone info (the GECOS field in /etc/passwd).
B3 | Which is FALSE?  (A) You can hash a password you already know and compare  (B) John reverses the hash to get the password back  (C) John the Ripper guesses over and over  (D) Hashes for local users sit in /etc/shadow	John reverses the hash to get the password back  [Hashes are one way. Cracking = guess, hash, compare.]
B3 | What is PAM, and who can change it?	Pluggable Authentication Modules - how Linux authenticates you. Admins configure it, and attackers with enough privilege can too.  [Config lives in /etc/pam.d.]
B3 | How does pam_exec.so get abused?	It runs any program during login, so an attacker gets a shell on every SSH attempt - even failed ones.
B3 | What does pam_pwhistory.so do?	Stops people reusing old passwords.
B3 | Read a shadow hash: $6$ vs $1$ vs $y$?	$1$ = MD5, $5$ = SHA-256, $6$ = SHA-512, $y$ = yescrypt. A '!' or '*' means no password login.
B3 | Why does a salt matter?	Same password, different hash on every account - so precomputed tables are useless.
B4 | Which definition is wrong?  (A) Polkit = command-line only, no GUI role  (B) sudo = run a command as someone else, set up by admins  (C) su = become another user  (D) runuser = admin runs a command as another user	Polkit = command-line only, no GUI role  [Polkit is the one used in GRAPHICAL environments.]
B4 | The 3 login record systems?	utmp (login & ssh), lastlog (PAM), systemd.  [Hook: U-L-S.]

B4 | Why does having 3 records help defenders?	Different programs write them, so wiping one still leaves the login in the others.
B4 | Where is sudo configured, and what edits it?	/etc/sudoers, edited with visudo (it checks your syntax first).  [sudo -l shows what you can run.]

B5 | 5 process tools?	ps, pidof, pgrep, pstree, top.  [Hook: Please Pick Pretty Process Trees.]

B6 | Which is FALSE?  (A) Deleting the original always breaks a hard link  (B) A symlink just stores a path, so it breaks if the target goes away  (C) Files map to inodes on devices  (D) A hard link is a second name for the same inode	Deleting the original always breaks a hard link  [Hard links keep the data alive - only the link count drops. Symlinks are the fragile ones.]
B6 | Hard link vs symlink?	Hard = same inode, same file system, files only. Soft = a path, can cross file systems and point at folders.
B6 | SUID, SGID, sticky bit?	SUID = runs as the file's owner. SGID = runs as the group. Sticky = in a shared folder, only the owner can delete their file (/tmp).  [find / -perm -4000 hunts SUID.]
B6 | Basic permissions and the extras?	rwx for user, group, world. Extras: immutable (chattr +i) and ACLs (getfacl/setfacl).
B6 | What does lsof show?	Open files and network sockets.
B6 | Lost the root password - how does mounting save you?	Boot rescue media, mount the disk, chroot in, reset the password. Same trick reads a Windows disk.
B6 | Why does the standard directory layout matter?	Every distro puts things in the same place: /etc config, /var logs, /home users, /usr software, /proc processes.

X | Extra lockdown layer: Linux vs Windows?	Linux: SELinux or AppArmor. Windows: integrity levels, which drive UAC.

X | Login records: Linux vs Windows?	Linux: utmp, lastlog, systemd. Windows: Security event log (4624), query user, psloggedon - all with limits.

X | Links: Linux vs Windows?	Linux: hard links and symlinks. Windows: shortcuts, hard links (files), junctions (folders), symlinks (admin only).

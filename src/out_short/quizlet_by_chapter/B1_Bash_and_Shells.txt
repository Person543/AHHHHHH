Which is FALSE?  (A) Bash can't use the network, so attackers ignore it  (B) You reach Linux through terminals and pseudoterminals running shells  (C) Bash keeps state in options, variables and environment variables  (D) A shell acts differently based on how it's configured and started	Bash can't use the network, so attackers ignore it  [Bash CAN talk over the network - reverse shells and exfil. That's why it matters to both sides.]
Which env variable is the security one, and why?	PATH. A writable folder early in PATH lets someone swap in a fake command.  [Fix: trusted dirs only, never '.', use full paths.]
Who wants Bash history, who doesn't?	Admins want it recorded. Attackers make sure it isn't.  [unset HISTFILE, HISTSIZE=0, set +o history, delete ~/.bash_history.]
Login vs non-login shell - why care?	They read different files, so the shell behaves differently. Login: /etc/profile + ~/.bash_profile. Non-login: ~/.bashrc.
Two Bash conveniences from 1.7?	Aliases (shortcuts for commands) and jobs (several tasks in one session).  [& , Ctrl+Z, jobs, fg, bg.]
